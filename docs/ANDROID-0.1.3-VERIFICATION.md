# Android 0.1.3 实机记录

2026-10-18，非 Root 小米 M610BB（系统报告 SM8950 / Android 17 / API 37）覆盖更新至 0.1.3 / versionCode 5，包名与原签名保持一致，没有卸载食迹或清除其数据。iPhone 版本未改动。

## 本次变化

- Hexagon NPU 自动选择、实际卸载检查及独立通用 CPU 回退。能力门槛、超时、24 小时失败冷却和手动开关见 [加速说明](ANDROID-ACCELERATION.md)。
- NPU worker 用私有管道复用已加载的模型，每张照片清空上下文并重建采样器（上游 `common_sampler_reset` 不清空 JSON grammar）。无网络监听端口。
- 会话内缓存营养表与别名索引，自定义食物改变后重新加载。空闲 60 秒后释放模型和目录缓存，内存压力时释放空闲会话。
- 模型权重、图片 token 上限、上下文大小与最多输出数量保持原配置，没有通过缩小图像或减少食材数来提速。

## 实际测量

单独的同签名测试 APK 调用**已安装的非 debuggable Release**，普通应用 UID 10341。仅使用仓库中的公开 Nutrition5k 图片，未使用私人照片；每次仍计算图像编码、提示词与答案。四次连续 NPU 调用中的后三次复用已加载模型，没有复用上一张的答案。

| 调用 | 耗时 | 备注 |
| --- | ---: | --- |
| NPU 第 1 张 | 14.0436 秒 | 加载模型、初始化 NPU 与识别 |
| NPU 第 2 张 | 6.4986 秒 | 同一会话，清空上下文后重新识别 |
| NPU 第 3 张 | 6.4735 秒 | 同上 |
| NPU 第 4 张 | 6.4053 秒 | 同上 |
| CPU 回退 | 36.8552 秒 | 模拟硬件不支持 NPU，使用独立通用 CPU 程序完成识别 |

后三张中位数 **6.4735 秒**，相对本轮首张延迟降低约 **54%**，主要节省重复加载/初始化与目录解析开销。CPU 回退只验证功能，本轮只有一次且使用通用 CPU 构建，不与之前优化 CPU 引擎的中位数混为一组。

同图重复次数少、执行顺序固定，未锁定频率或温度，文件缓存可能已热；上述首次指“新 worker 会话”，不表示清空操作系统缓存后的冷启动。模型可能给出与 CPU 不同的食材/份量，输出有效 JSON 不代表热量准确。没有测量电量收益、长时间锁屏、多日后台运行或所有机型。

iPhone 先前一次缓存后 Metal 调用为 4.60726 秒、第一次 13.36095 秒。它们不是本次同时控制条件的对照，不能据此宣称芯片或平台的稳定性能排名。

## 验证结果

- **26 项正式包检查通过**：非 debuggable Release、既有模型就绪、四次食物 JSON、四次预期后端、四次 HTP0 会话/25 层语言模型/HTP0 视觉卸载检查、四次复用状态、目录缓存、自定义修改使缓存失效、模拟不支持 NPU 时真实 CPU 推理、失败冷却、取消、个人设置/自定义食物不变及无餐食记录增删。
- **23 项 JVM 测试通过**：原营养与读取边界 16 项，加速器故障重试、取消不回退、CPU 错误传递和架构/CPU 能力门槛等 7 项。
- Release 构建与 lint 通过。旧版、新版与测试 APK 的签名证书一致；最终安装包不含测试 instrumentation 或公开图片。
- 测试只在独立偏好文件中创建临时自定义食物，结束后删除并释放 worker；扫描任务在测试期间短暂停止，之后恢复。允许后台扫描运行状态更新，个人设置则完整比较。

[机器可读记录](verification/android-0.1.3/release-verification.json)包含本轮耗时、检查列表与 APK 哈希。功能验证后只更新了 `assets/models.json` 中的后端文字说明；逐项比对 APK 确认 DEX、原生程序和其他资源完全一致。最终说明修订后的 APK 也覆盖安装到手机。

当前是 V85 设备上的 V81 兼容路径。其他手机（包括未接入测试的小米 15）、较低 Android 版本、低内存条件、原生 V85 调优和更长时间稳定性仍需单独验证。缺少受支持能力的手机按设计使用原 CPU 程序，不能把此回退设计写成已覆盖所有机型的实测结论。
