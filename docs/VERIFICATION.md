# 食迹 0.1.0 实测记录

日期：2026-10-18。设备读取为 Xiaomi 18 Pro（M610BB），SM8950，Android 17 / API 37，约 16GB RAM。应用 targetSdk 36，最低 API 30，ARM64。测试使用公开 Nutrition5k 图片和应用自己创建的媒体项，不读取个人相册做测试。

## 已通过

- Debug / Release APK 编译，Android Lint 无错误，13 项确定性营养与建议规则单元测试无失败。
- 17 项手机功能检查：营养数据加载、150g 米饭与 5g 油的数据库计算、估算范围保留、未知食物标记、异常份量拒绝、实际食用比例重算、清理条件、原图重新检查、系统相册收藏保护、应用收藏保护、未确认照片保护、JSON 不导出照片 URI、模型哈希校验、随包食物初筛、普通应用 UID 中视觉推理、结果解析、设备无系统 su 二进制。
- 普通应用 UID 为 **10341**。视觉进程从应用已安装的原生程序目录运行，读取应用私有模型与照片；没有调用 su 或使用 shell UID 进行应用识别。
- 两次普通应用中的公开样例视觉调用分别约 **30.79 秒、25.07 秒**；不是平均延迟或性能保证。CPU 4 线程，未使用 NPU/GPU。
- **后台链路实测通过**：注册任务后写入由应用创建的公开餐食图片，关闭主界面，系统内容任务自动发现并识别，数据库状态变为 `estimated`，`confirmed=false`。周期任务 100 为持久化 15 分钟补扫，内容任务 101 注册 MediaStore 变化。
- 测试过程中实际可见完整照片访问已授予、自动发现开启。未更改用户个人资料。测试图片与对应记录在结束后删除。
- 手机界面验证：首页、设置、餐食列表、模型就绪状态与待确认标记。未确认记录不会被当作已核对的完整摄入。
- 原生 ELF 为 ARM64 PIE，仅依赖系统 libc/libm/libdl，LOAD 段为 16KB 对齐。APK 签名与 ZIP 对齐检查执行于最终交付流程。

## 准确度方面的实际发现

公开混合餐食样例被识别为“沙拉”，模型仍漏掉图中的部分其他食物。同一内容经过不同 JPEG 处理后，测试记录曾给出约 **277.2 kcal** 与 **96.5 kcal**，其中用油与部分食材也不同。**这说明链路能运行，不说明热量已经可靠。** 本项目尚未用大量称重样本校准，不能将设计的估算区间视为误差保证。

因此所有视觉记录先保存为草稿；用户需要核对食材、用油、重量和实际食用比例，才能确认。加餐参考还要求记录完整度核对，并为后续正餐留出空间。当前版本适合试用记录流程，不能据此承诺无需人工纠正的减重指导。

## 尚未验证或尚未交付

- Xiaomi 15 实机、其他 Android 版本与低内存设备；当前仅基于 Android 公共 API 和 ARM64 CPU 路径保持兼容设计。
- 24 小时或数周的锁屏触发率、HyperOS 各种省电模式、重启后完整长时间行为与实际电池消耗。
- NPU / QNN / QAIRT 加速，未把 CPU 推理当作 NPU 成功。
- 多菜中餐的总体识别准确率、份量/热量误差、饮料与包装食品完整覆盖。
- 桌面小部件的所有启动器排列、真实月末通知与批量清理用户原图。清理规则与收藏保护经过检查，但本次没有删除任何用户照片来验证功能。
- 首版月度整理需要用户批量确认，不支持无交互的定时删除。
- 模型 ZIP 导入、网络中断续传的全部异常路径尚未做长时间实机覆盖；当前连接手机的模型通过 USB 安装并经应用内 SHA256 校验。

交付验证包包含单元测试 XML、Android Lint 文本、应用自检 JSON、后台结果 JSON、构建日志和 APK 校验结果。只包含公开样例的识别结果，不包含个人照片、个人资料或相册清单。
